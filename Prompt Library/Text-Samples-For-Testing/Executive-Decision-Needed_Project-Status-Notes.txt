## Real-Time Recommendation Engine
Status: OFF TRACK
Teams: Data Science & AI, Backend Engineering, DevOps & Infrastructure

The real-time recommendation engine — intended to replace our batch-based
collaborative filtering system — is significantly behind schedule and facing
compounding technical and budget issues. Model latency is 3x the 150ms SLA
target, cloud costs are running 240% over budget, and the feature store that
Backend Engineering was supposed to deliver 3 weeks ago has still not arrived.
An executive decision on path forward is urgently needed.

Accomplishments:
- Candidate generation model v0.4 achieving 78% relevance@10, up from 71% in v0.3
- A/B testing infrastructure deployed and validated
- Initial feature store schema designed and reviewed

Risks:
- CRITICAL: Model inference latency at 450ms P99 against a 150ms SLA. Root
  cause is the two-tower architecture. Team is evaluating ANN caching as
  mitigation but that work is not currently scoped.
- HIGH: Cloud compute costs for training are $47K/month against a $20K budget.
  Unsustainable without an architectural change or budget increase.
- HIGH: Feature store not delivered by Backend Engineering (3 weeks overdue, no
  confirmed date). Data Science team is using a temporary workaround that will
  not scale to production.
- MEDIUM: No schedule buffer for ANN caching work — any further delay pushes
  past the Q3 board commitment.

Dependencies:
- BLOCKED: Feature store delivery from Backend Engineering. This is the single
  biggest technical blocker on the project.
- DevOps must provision GPU cluster expansion before retraining can scale —
  requires budget approval first.
- Real-time A/B testing requires UI surface area coordination with the Customer
  Portal Redesign team.

Executive decisions needed:
- CRITICAL: Project will miss Q3 deadline and is over budget. Three options for
  leadership decision: (1) Increase cloud budget $60K/month and maintain full
  scope, (2) Descope to a simpler matrix factorization approach that can hit the
  timeline, or (3) Push to Q4 and build the real-time engine correctly. Team
  recommends option 2 or 3. Decision needed by Thursday.
- If option 1 is chosen: GPU cluster expansion budget approval required.

Immediate next steps:
- Data Science & AI: present ANN caching feasibility and the 3 path options to
  leadership by Thursday
- Backend Engineering: provide firm delivery date for feature store this week
- DevOps: right-sizing cost analysis for GPU cluster

Long-term next steps:
- If descoped (option 2): deploy matrix factorization model by Q3; plan
  real-time engine for Q1 next year
- Regardless of path: implement MLflow model registry for proper experiment
  tracking and reproducibility
